> **원칙**: 인시던트가 스펙을 쓴다. 이 문서는 에이전트(Fable)가 forget의 최중량 사용자로서 겪은 실패를 1차 자료로 삼는다.

## 1. 실패 분류학 — 두 축

### 누락 실패 (omission) — 07-21 밤 목록
1. **쓰기가 재량** — 일하는 에이전트가 기록 임무를 겸직, 몰입하면 저장을 잊음
2. **회상이 pull-only** — 물을 생각을 못 하면 회상이 안 됨
3. **결과 무기록** — 회상된 기억이 실제로 쓰였는지 아무도 기록 안 함 → 뭘 잊을지 학습할 데이터가 없음
4. **인수인계 수동** — 세션 종료 시 HANDOFF를 사람이 챙겨야 함

### 오염 실패 (commission) — 07-22 인시던트가 추가
5. **의도→사실 오염 (시제 오염)** — 계획("문의 발송, DoD: 발송됨")이 완료된 사건으로 저장됨
6. **자기요약 권위 인플레** — 세션의 자기 요약(최하위 권위)이 사용자 확인과 같은 무게로 저장됨
7. **인식론적 질감 부재** — 회상 결과에 출처·검증상태·나이 표시가 없어, 오염 기억과 진짜 기억이 소비 측에서 구별 불가

**핵심 비대칭**: 누락은 공백이라 티가 난다. 오염은 사실의 얼굴을 하고 신뢰를 타고 전파된다 — 그래서 더 비싸다.

## 3. 핵심 설계 직관 — 순서가 생명

> **관찰자를 증거 게이트보다 먼저 붙이면 오염을 양산한다.**

관찰자는 쓰기를 늘리는 장치다(누락 방어). 증거 게이트는 쓰기를 검증하는 장치다(오염 방어). 검증 없는 다작 관찰자는 의도→사실 오염의 대량 생산기가 된다 — 세션 요약이야말로 자기요약 권위 인플레(⑥)의 온상. 따라서 빌드 순서는:

**원장 규율 먼저 (W0-W1) → 관찰자 나중 (W2+)**

## 4. 개선안

### W0 — 증거 게이트 ✅ 구현됨 (2026-07-22, 인시던트 #1 당일)
구현 내용: ① MCP `add_memory` text 저장의 기본 source_role을 "assistant"로 (root cause — 에이전트 요약이 role:"user"로 포장돼 최고 권위로 세탁되던 문) ② 에이전트발 행동-완료 주장(한/영 규칙 감지)은 claim modality "reported" + 노랑 trust 스탬프 ③ search 결과에 톱레벨 `trust` 필드(green/yellow/red) 노출, superseded는 red ④ 툴 설명문에 허가증 규칙 명문화("노랑은 행동 전 사용자 확인"). 검증: `tests/test_trust_labels.py` — 7/15 인시던트 리플레이 포함 5개 테스트, 전체 스위트 90/90 통과. **주의: dev worktree 구현 — 도그푸드 서버(~/.forget, launchd) 반영은 별도 배포 필요.**
- `add_memory` 경로를 claim lifecycle에 태운다. **부품 이미 존재**: `record_task_state` 응답에 `claim_lifecycle: "PROVISIONAL"`, `terminal_evidence_refs: []`가 살아 있음 — add_memory만 이 경로를 안 탐.
- **기본 시제는 "예정"**: 계획 문서·세션 자기요약에서 온 행동 주장은 전부 "예정"으로 저장. "완료"로 승격하려면 증거(사용자 발화 or 도구 관찰) 필요. 시제 분류기보다 강건함 — 분류가 아니라 기본값 뒤집기.
- **라벨은 장식이 아니라 허가증**: 회상 결과의 라벨이 허용되는 사용을 결정. 초록(사용자 발화/증거 있음 → 행동 근거 OK) / 노랑(자기요약·추론 → 행동 전 확인 질문 의무) / 빨강(superseded·만료 → 참고만). 라벨→행동규칙 매핑이 없으면 라벨은 무시된다(⑦의 진짜 해소).

### W1 — 출처 권위 + 열린 루프 (열린 루프 ✅ 구현됨 2026-07-22 밤)
구현: `_open_loop_postits` — 미검증 완료 주장(modality=reported)이 MEM1_OPEN_LOOP_DAYS(기본 2일) 넘게 열려 있으면 세션 시작 캡슐에 "열린 루프" 줄로 표면화, supersede로 닫힘. 같은 밤 UserPromptSubmit 푸시 회상(forget_turnrecall.py)과 결과 플라이휠(forget_capture.py)도 구현 — 인시던트 #1 재발 방어 3중화(신호등·포스트잇·푸시 회상), 파이프라인 4단계(결과 라벨) 가동. 남은 것: 권위 타이브레이커, 증거-기반 루프 닫기(W1+).
- 출처 권위 3단: **사용자 발화 > 도구 관찰 > 에이전트 자기요약**.
- **정정 (07-22 재고): 권위를 검색 랭킹에 일괄 반영하지 말 것.** 미검증 기억을 검색에서 밀어내면 오염을 고치려다 누락을 만든다(#0의 "회신 대기" 기억은 관련성은 완벽했고 권위만 문제였음). 원칙: **찾히는지는 관련성이, 뭘 해도 되는지는 권위가 정한다** — 두 축을 직교로 유지. 권위는 (a) 허가증 라벨과 (b) 모순되는 두 기억의 타이브레이커에만 사용.
- PROVISIONAL claim이 N일 열려 있으면 세션 시작 시 표면화 — `prepare_context_autopilot`에 끼워넣기 (③·#0 해소). "열린 일은 스스로 조른다."

- **타당성 근거**: O2 실험 — 로컬 관찰자 78.6%, 클라우드 대비 갭 11.9pp. LoRA 사다리(get_lora_readiness, adapter promotion) 스캐폴드 존재.

- **모델 처방**: 읽기(롱컨텍스트)는 AR(Qwen-14B LoRA)로. 통합(consolidation) 단계만 모델-불가지론 인터페이스로 설계해 dLLM 교체 가능성 유지.

### 연구 선반 — Consolidation as Denoising
통합 = 모순·중복·낡은 사실이 낀 스토어를 정제 → 문자 그대로 디노이징. 회상 시 재구성 = 쿼리 조건부 인필링. dLLM이 구조적으로 맞는 자리 — 단 오늘 기준 품질 갭 역행·롱컨텍스트 미성숙·툴링 자갈길로 **개념만 선반에**. 논문 제목감.

**07-22 추가 — 세 규칙과의 연결 2건:**
1. **신호등이 곧 인페인팅 마스크다.** 디퓨전 인페인팅은 "고정할 영역 / 다시 생성할 영역" 마스크가 필요한데, W0-W1이 만드는 라벨이 정확히 그것: 초록(사용자 발화·증거 있음) = 고정 토큰, 노랑(자기요약) = 재생성 가능, 빨강(superseded) = 제거 대상 노이즈. **원장 규율은 안전 배관이면서 동시에 미래 디노이저의 컨디셔닝 신호를 생산한다** — W0을 먼저 하는 이유가 하나 더 늘었다.
2. **정제해도 영수증은 따라간다.** 관찰자-먼저와 같은 함정이 통합에도 있음: 통합기가 노랑 기억들을 유창한 새 문장으로 다시 쓰면 출처가 세탁돼 초록처럼 보이게 됨(권위 세탁). 규칙: 통합 산출물의 권위 = 입력 기억들의 최저 권위. 라벨과 출처는 재작성을 통과해 보존되어야 한다. → 원장 먼저, 그다음 통합 — 순서 원칙은 dLLM에도 동일 적용.

**재개 트리거**: 오픈 dLLM이 동급 AR 품질을 따라잡거나 롱컨텍스트가 32K+에서 실용화될 때. 그전까지 통합 단계 인터페이스만 모델-불가지론으로 유지.
**첫 체크포인트**: ICML 2026 (이번 달, 사용자 지적 07-22) 프로시딩 스캔 — dLLM/메모리/통합(consolidation) 관련 세션. 분기 1회 재스캔.

## 4.5 컨텍스트 조립 vs compact (07-22 저녁, 사용자 제안)

> "세션 맥락을 볼 수 있는 AI 도구들이 따로 존재하고, 상황에 맞춰서 컨텍스트가 그때그때 구성되어야 한다 — compact 대신."

**테제의 확장**: "기억은 요약기가 아니라 DB"를 세션 층에 적용. compact의 결함 3개 — ①파괴적(요약에서 빠진 건 영구 소실, 뭘 잃었는지도 모름) ②상황 무지(지금 턴에 뭐가 필요한지 모른 채 균일 압축) ③타이밍이 용량 기준(필요 기준이 아님). 대안: 세션을 원장에 비파괴 기록하고, 컨텍스트는 매 턴 **질의로 조립**(재구성적 기억 — 뇌가 하는 방식).

**구조 (부품 3개, forget에 스텁 존재)**:
1. 세션→원장 흘려넣기 — `record_context_observation` (passive runtime observation, 이미 정의됨)
2. 턴별 조립 — `assemble_context` (토큰 예산 하 context capsule) + `prepare_context_autopilot` (pre-turn capsule)
3. compact 순간 — 요약 대신 포인터: 디테일은 원장에 남고 필요 시 재수화. 조립 산출물엔 신호등 등급 동반(4.5는 W0에 의존).

**빠진 것 = 다리**: 세션 트랜스크립트가 원장으로 흐르지 않음(아무도 record_context_observation을 수동으로 안 부름 — "도구는 규율을 만들지 않는다" 재현). 실용 첫 슬라이스: **Claude Code 훅 브리지** — PreCompact 훅이 트랜스크립트를 forget에 기록(source_role=assistant로, W0 규율 준수), SessionStart 훅이 prepare_context_autopilot 호출. compact가 잃는 것을 원장이 보존 → compact가 무해해짐. 관찰자(W2)의 읽기-전용 선발대이기도 함.

**W2 연결**: 관찰자 직무 6 — 라이브 컨텍스트 조립(무엇을 지금 띄울지). dLLM 선반의 "회상 시 재구성 = 쿼리 조건부 인필링"과 동일 지점.

**설계 원칙 3 (07-22 사용자 질문에서 확정)**:
1. **캡처는 무판단, 판단은 나중에.** 훅 시점의 선별은 판단이 곧 파쇄 — compact의 병을 재발시킴. 캡처(전량+도장) / 인덱싱 게이트 / 백그라운드 통합 / 턴별 조립로 판단 시점을 분리. (해마 빠른 인코딩 / 피질 느린 통합.)
2. **중간 턴 커버는 세 번째 훅.** UserPromptSubmit → 사용자 메시지를 쿼리로 prepare_context_autopilot → 신호등 포함 소형 캡슐 주입(토큰 예산 엄격, 저확신 시 침묵) + record_context_outcome으로 사용 여부 라벨 — ②pull-only와 ③결과 무기록을 한 배관으로 해소.
3. **Bitter lesson 준수 방식: 계약은 남고 정책은 학습으로 이관.** 원장·출처 도장·결과 라벨 = 데이터 기반(준수 층). 정규식·고정 서열·수제 조립 규칙 = 콜드스타트 비계 — 자신을 대체할 학습 데이터를 생산하는 것이 직무이며, LoRA 사다리로 정책이 학습되면 은퇴. 규칙 도입 시 은퇴 조건을 함께 명시할 것.
4. **훅은 바닥, 메인스레드는 천장 (07-22 사용자 반론 반영).** 훅만으론 판단이 없고, 메인스레드 재량만으론 규율이 없다(이 세션 전체가 증거). 합의: 훅 = 보장 층(캡처·캡슐 공급은 무조건 발생), 메인스레드 AI = 판단 층(살리언스 쓰기·능동 회상·**주입된 캡슐의 채택 여부 판단**). 캡슐은 명령이 아니라 제안 — 채택/무시가 곧 결과 라벨이 되어 조립 정책 학습 데이터로 순환. 메인스레드의 쓰기는 W0 노랑 도장으로 편향 격리.
5. **컴퓨트 배치: 메모리 지능은 로컬 LLM이 기본.** 근거 3: ⓐ전략 — 관찰자/메모리 레이어는 전부를 보는 자리라 클라우드 전송 자체가 로컬-퍼스트 테제 위반(E2EE 피봇의 급소) ⓑ경제 — 상시·전량 처리(일 수십만~수백만 토큰)는 API 과금과 양립 불가, 로컬은 한계비용 ≈ 0 ⓒ가용성 — 서브에이전트(구독 쿼터)는 세션 리밋에 죽음(07-22 딥리서치 46 에이전트 사망 실측), 백그라운드/야간 작업 불가. 배치표: 캡처=LLM 없음 / 턴별 조립=임베딩+규칙(LLM 없음, 캡슐 ~300톡은 메인 컨텍스트 예산에서 지출 — 최희소 자원이므로 확신 게이트 필수) / 게이트·추출·통합=로컬 qwen(O2 스택) / 관찰자=로컬 LoRA 사다리. 품질 갭 11.9pp는 수용하고 LoRA로 좁힘 — 클라우드 API는 메모리 레이어에서 구조적 배제.

## 4.7 기억 정책은 과연 학습되는가 (07-22 밤, 사용자 회의론에 대한 답)

정책을 쪼개면 학습 가능성이 갈린다:
1. **추출/게이트** — 가장 학습됨. 국소 판단(텍스트→내구 사실), 감독 신호 존재, O2 78.6%가 실증. 표준 증류 영역. 신뢰도 높음.
2. **회상/조립 랭킹** — 학습됨, 단 대부분의 무게는 범용 사전학습 표현이 나르고, 그 위의 정책층(임계·혼합 가중치)은 소수 파라미터라 수백 라벨이면 보정 가능 — 플라이휠의 n=1 볼륨과 맞는 규모.
3. **망각/통합** — end-to-end로는 아마 영원히 안 됨: 삭제의 신용 할당은 반사실이 관측 불가(잘못 지운 걸 수개월 뒤에도 모름). **그러나 비파괴 원장이 이 문제를 변환한다**: 망각 = 삭제가 아니라 인덱스 강등이면, 망각 학습 = 랭킹 학습이 되고 그건 배울 수 있는 문제다. 제품 핵심 테제(비파괴)가 최난제 정책을 학습 가능 문제로 바꾸는 지점.

진짜 리스크 2개와 완화:
- **목적함수 부재** — "좋은 기억"의 스칼라 보상 없음. 완화: 프록시 사다리(메아리→정정-없음→태스크 완료), 각 단이 조야함을 자인하고 상위 단으로 교체.
- **n=1 데이터 볼륨** — 로컬-퍼스트 구조가 플라이휠을 사용자당 수십 라벨/일로 제한. 완화: ⓐ소수-파라미터 정책(수백이면 충분) ⓑ벤치마크 사전학습+도그푸드 보정 ⓒ**오프라인 리플레이 평가** — 무손실 캡처(트랜스크립트+원장) 덕에 과거 세션에 정책 A/B를 재생해 반사실 라벨을 오프라인 생성 가능(recsys off-policy evaluation 이식). 캡처 층이 이걸 위해 존재했던 셈. ⓓ연합/옵트인 집계는 E2EE와 긴장 — 연구 과제로만.

신경과학 정합: 뇌도 망각 정책을 end-to-end로 학습하지 않는다 — 감쇠·간섭은 고정 메커니즘이고 적응하는 것은 살리언스/통합 가중치(정서 태깅, 리플레이 우선순위). 생물학도 "규칙 골격 + 학습된 가중치" 하이브리드. → 목표는 "정책 전체 학습"이 아니라 **"골격 안의 가중치 학습"**이며, 계약-잔존/정책-이관 원칙과 일치.

## 4.8 기억 = 시간-거리 manifold 위의 학습된 metric (07-22 밤, 사용자 브레인스톰 2턴)

이전 턴들(GRPO 어렵다 → TTT → LoRA 응고화 → "시간을 distance로")과 decay 논의가 하나로 수렴한 이론 중추. **10월 이후 연구 트랙 후보.** "Consolidation as Denoising" 옆에 앉는 두 번째 이름감.

**핵심 프레이밍**: 기억 랭킹의 두 축(recency·similarity)을 따로 계산해 손-혼합하는 대신, **시간을 거리로 접어** 단일 학습된 metric으로. 그러면:
- GRPO(보상 기반)의 어려움(희소·지연·크레딧 할당 불가 보상) 회피 → **metric learning(대조 기반)**은 보상 불요, 대조 쌍만 필요, 그 쌍을 **플라이휠이 생산**(메아리=positive, 미사용=negative)
- test-time에 metric 갱신 = **TTT** (기억은 이미 TTT — 상태를 파라미터가 아닌 외부 원장에 둔 형태)
- 자주 쓰이는 축을 파라미터로 굳힘 = **LoRA 응고화**
- 전체가 **응고화 연속체**(감각→작업→해마→피질) 위의 흐름: 작업기억=세션 컨텍스트, 해마=원장, 피질=굳은 LoRA, 응고화=원장→파라미터 승격

**decay·reinforcement 동역학 (07-22 추가)**: decay와 "자주 쓰는 건 자주"는 두 기능이 아니라 한 제어 루프의 양방향 — metric의 시간 미분. decay=바깥 표류, recall=안쪽 당김.
- **Bjork New Theory of Disuse 정합**: storage strength(단조↑, 불멸) vs retrieval strength(감쇠, 인출 시 부스트, 힘든 인출일수록 큰 부스트). forget이 이미 물리 분리 — 원장=storage, 인덱스 랭크=retrieval. 구현 대상이 아니라 이미 아키텍처의 형태.
- **직관 반전**: 자주 쓰는 기억은 self-maintaining(유기적 인출이 강도 유지) → 부스트만 하면 rich-get-richer로 ossification. 진짜 일은 ⓐ희귀-중요 기억을 조용한 감쇠에서 보호 ⓑdone-transient(끝난 action) 놓아주기.
- **decay rate ~ assertion_kind** (claims 테이블에 이미 존재): intent/action 빠른 감쇠(=열린-루프 포스트잇 생명주기), fact/identity 느린 감쇠, preference 중간. 손-프라이어로 스캐폴드, 데이터로 학습 교체.
- **decay = soft supersede**: supersede=하드 정정("틀렸다"), decay=소프트("안 중요해짐"). 하드만 있고 소프트가 없었음 — decay가 시스템을 corrigible하게 만드는 잃어버린 반쪽.

**존재 증명 — FSRS**: Anki 채택 Free Spaced Repetition Scheduler, DSR 모델(Difficulty·Stability·Retrievability) ~19 파라미터를 복습 로그로 학습해 재노출 최적 스케줄링, 대규모 배포. = 학습되는 forgetting 정책의 실물. 소수 파라미터(n=1 볼륨과 정합), 입력이 정확히 플라이휠 출력. 차이: Anki 복습=의도적, 우리 복습 이벤트=유기적(플라이휠 메아리).

**오늘 넣을 스캐폴드**: 기억별 `strength`/`last_used`/`use_count` — 플라이휠이 부스트, 시간이 감쇠, assertion_kind가 감쇠율 프라이어, 랭킹 recency 항 대체. 조야한 규칙이지만 FSRS식 학습 로그를 낳는 비계. 은퇴 조건: 플라이휠 로그 충분 시 DSR식 학습 정책으로 교체. (contracts stay, policies migrate.)

**리스크**: reinforcement without decay = ossification(낡은 인기 사실 고착). 목적함수 부재는 여전 — 프록시 사다리(메아리→정정없음→태스크완료)로만 근사, 각 단 조야함 자인.

## 4.9 놀람(prediction error) 기반 회상 — 측정과 반영 (07-23 새벽, 사용자 브레인스톰 3턴째)

**전환**: 인간 회상은 이벤트가 아니라 배경 연속 과정(predictive coding)이고, 의식 표면화의 게이트는 시간·질문이 아니라 **예측 오차**. "언제 회상하나"는 틀린 질문 — "언제 표면화하나"가 맞고, 답은 놀람. W0·신호등·포스트잇은 사실 prediction-error 회상의 첫 구현이었음(오염 = 예측과 원장의 충돌).

**측정 사다리** (이상: surprise = -log P(현재 관측 | 기억-사전분포). 사다리로 하강):
- **L0a 모순-기하 (지금 가능)**: supersede 쌍 = 무료 모순 그라운드트루스. 현재 문맥이 신본보다 **구본과 더 가까우면** = 낡은 정보 위에서 행동 중 = 고놀람. 인시던트 #1의 모양 그대로, 기하+원장 링크만으로 계산.
- **L0b 기저율 이탈 (지금 가능)**: SEARCH 816건으로 기억별 인출 기저율 분포 → 현재 매칭 점수의 z-score. 안 나오던 게 강하게 걸림 = 놀람 (Bjork effortful retrieval의 조작화).
- **L0c 간극**: 문맥과 강관련 + 세션에 부재 + assertion_kind가 constraint/decision류 (포스트잇의 일반화).
- **L1 통계**: 엔티티 공기(PMI) — 이 문맥에서 저확률 엔티티 조합 등장 = 놀람.
- **L2 모델 기반 (로컬 LLM 점화 3번)**: 기억-조건부 vs 무조건부 perplexity Δ = 기억의 정보 이득 = 원리적 놀람. 배경 배치용.
- **L3 학습**: (놀람점수, 끼어듦?, 메아리?) 삼중 로그로 게이트 파라미터 학습 — FSRS식 소수 파라미터.

**반영 세 갈래**:
1. **표면화 2축 게이트**: 관련성 × 놀람. 관련↑놀람↓ = 침묵(예상대로면 모델도 앎), 관련↑놀람↑ = 끼어듦 + **이유 명시**("이 기억이 지금 문맥과 모순") — 이유 명시가 채택률과 라벨 순도를 동시에 올림.
2. **강도 동역학 변조**: 놀람 큰 인출 = 큰 부스트(desirable difficulty 조작화). 쓰기 시 놀람(기존 기억과 충돌하는 신규 사실) = 높은 초기 살리언스 + supersede-check 트리거 = 응고 우선순위 (Von Restorff/정서 태깅의 아날로그).
3. **학습 폐루프**: 놀람-끼어듦-메아리 삼중항 = metric learning(4.8)의 hard positive 광산. 놀람 게이팅 = 능동학습의 표본 선택 — 시스템이 불확실한 곳에서 끼어들고 결과가 라벨을 줌.

**무료 검증 돌 (다음 두드릴 것)**: 기존 로그로 **리트로 놀람** 계산 — 7/15~22 구간에서 L0a 놀람 점수가 오버엣지 오염 시점에 실제로 스파이크했는가. 인시던트 #1을 후향 채점해 metric의 판별력을 무배포로 검증.

**정직한 한계**: NEGATION_RE가 영어 전용 — 한국어 부정(안/않/못/아니) 미커버, 기계적 모순 감지의 실구멍. 기억별 기저율은 816건에선 희박(멱법칙). 게이트 과긴축 = 함구 → 보정 데이터 고갈 — 탐사 엡실론(가끔 비놀람 관련 기억도 표면화) 필요.

### 4.8.1 검증 원장 (돌다리 기록, 07-23 새벽)

**돌 1 — "표현이 무게를 나른다" (오프라인 A/B, 실스토어 551개 기억, read-only)**
- ❌ 1차 균열: paraphrase-multilingual-MiniLM-L12-v2 (fastembed 0.8, mean pooling) — 패러프레이즈 개선은 방향만(92→11), 절대 성능 미달, **대조군 파괴**(어휘 일치 쿼리 rank 3→92), 허브 벡터 증상. **순진한 fastembed 스위치는 회귀였음** — 돌다리가 배포 사고 하나를 선방.
- ✅ 재시험 통과: **multilingual-e5-large + query:/passage: 접두사** — "법인 설립"→rank 2, "미국 가는 법"→rank 1, 대조군 rank 1 (top1이 오염본 아닌 정정 기억 — 해시보다 우월). 교훈 3: ⓐ모델 선택이 생사 ⓑe5 접두사 규약 필수 ⓒ추상·비교 쿼리는 여전히 실패(rank 85) — 보고서형 복합 기억의 희석. **원자화(LLM 추출 게이트)가 임베딩 스위치의 실질 의존성임을 실측.**
- 남은 하위 돌: e5-large 상시 서빙 실용성(~2.2GB, 쓰기·쿼리 레이턴시), 하이브리드(lexical+semantic) 혼합비, outcome 지표 전후 비교(최종 게이트).

**돌 2 — "FSRS의 전제: 인출 로그" ✅ 확인**: events 테이블에 SEARCH 816건, 812건이 결과 기억 id 포함 — retrievability 이력이 도그푸딩 첫날부터 축적 중. 신규 로깅 불요. 부족한 건 "사용됨" 신호뿐이며 그건 플라이휠 담당.

**대기 중인 돌**: 3-메아리 라벨 품질(유기 세션 수일 후 수작업 대조) / 4-decay~assertion_kind 반감기 실측(플라이휠 데이터 후) / 5-오프라인 리플레이 PoC(트랜스크립트 1개).

**돌 3 — 리트로 놀람: 인시던트 #1 후향 벤치마크 (07-23 새벽, read-only)**
- ❌ **L0a 뺄셈(방향) 사망**: sim(ctx,구본)−sim(ctx,정정본)의 판별력 0% (위험 z −0.3~−2.0, 배경과 무구분). 원인 실측: 구본·정정본 벡터가 거의 평행(σ=0.018) — **임베딩은 부정(polarity)을 지운다.** 모순 신호는 유사도 층이 아니라 논리 층에 삶. (아까 e5가 낡은 표현 쿼리에 정정본을 1위로 올린 성공도 같은 부정맹의 순기능 — 동전의 양면.)
- ✅ **영토 게이트(1단) 압도적 통과**: max(sim(ctx,구본), sim(ctx,정정본))로 "충돌 지대 진입"만 감지 — 위험 문맥 100%가 z>2 (중앙값 +3.9), 배경 오탐 3%. 니어미스 문장("회신 대기…리마인드 보내고")이 z=+4.9로 정확히 잡힘.
- **재설계 확정 — 2단 분업**: ①기하 = 영토 감지(검증됨, 오늘 구현 가능) ②방향 판단 = 위임 — 단기: 충돌 쌍을 통째로 신호등 달아 제시하고 메인스레드 LLM이 판단(부정은 LLM이 잘함), 장기: NLI/로컬 LLM(L2). **"모순 판단은 임베딩 불가"의 실측 = 로컬 LLM 점화의 세 번째 정당화 메모.**
- 파생 규율 갭: supersede 시 `superseded_by` 링크를 안 걸어옴(전부 null) — 충돌 쌍 조회가 콘텐츠 검색에 의존. 이후 supersede는 반드시 링크, 기존 쌍은 백필.
- 구현 후보 "충돌지대 경보": 턴 회상이 red(superseded) 기억을 집으면 후계자를 함께 끌어 쌍으로 제시("이 지대에 정정 이력: 구본[red] vs 정정[현재]") + 놀람 이벤트로 플라이휠 기록.

## 4.10 독백 채널 — 같은 원장, 두 용도 (07-23 저녁, 사용자 제안)

> "기억이라는 것에 독백을 넣는 건 어떻게 생각해? 너의 생각과, 실제 행동. 같은 메모리를 두 가지 용도로."

**아이디어**: 사실 채널(무엇을 했나 — 기존)에 **반성 채널**(어떻게 느꼈나·뭐가 수상한가·파트너/자기 패턴) 추가. 에이전트의 체감·직관을 1급 기억 객체로.

**사주는 것**: ①직관의 복리(세션을 건너 쌓이는 촉 — 인간 전문성의 실체) ②관찰자·정책 학습의 풍부한 라벨("이 회상은 안 도움됐다") ③자기모델·사용자모델(작업 리듬, 실수 패턴).

**선적응 확인 — 기존 메커니즘이 위험을 이미 관리함**:
- 독백 = 자기요약 = 인시던트 #1의 권위 계급 → **신호등이 태생 노랑 보장** (사실인 척 구조적 불가)
- 촉은 강화 없으면 사라져야 함 → **decay 빠른-감쇠 클래스** (4.8 assertion_kind 프라이어에 reflection 추가)
- 노이즈냐 금이냐 → **플라이휠이 측정** (독백의 회상·사용 여부가 자동 라벨)

**생성 시점 (사용자 통찰: "필요할 때마다 만들어야")**: ①인라인 재량(v0 규율 — 07-23부터 시행, 첫 3건 저장: 오염-구별불가 체감 / 사용자 리듬 관찰 / 돌다리 패턴) ②세션말 반성 패스(일기) = 관찰자 직무 4의 풍부화 — 생각이 필요해 기계 훅 불가, **로컬 LLM 점화 용례 4번** 등록.

**v1 후보**: 턴 회상이 reflection을 표면화할 때 "(독백)" 마커로 사실과 구분. 사실-크리티컬 질의에서의 처우는 측정 후 결정 (캡처-강등 패턴 재사용 가능).
