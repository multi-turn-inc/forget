# 프록시-네이티브 재설계 (2026-08-12, 정훈 지시: "유저가 신경 안 쓰게 + 프록시에 맞게 재설계")

전제 전환: 프록시는 캡처 부품이 아니라 **데이터 평면의 척추**다. 쓰기 경로의
정본 원료층(L0)이 CC 트랜스크립트에서 프록시 스트림으로 이동한다.

## 1. Zero-config 설치 (유저는 프록시의 존재를 모른다)

- `forget-connect`가 설치 시: ① launchd `ai.forget.proxy` 등록 (KeepAlive —
  ai.forget.server와 동일 규약) ② `~/.claude/settings.json`의 `env`에
  `ANTHROPIC_BASE_URL=http://127.0.0.1:8377` 기입.
- **기존 base URL 존중**: 유저가 이미 커스텀 게이트웨이를 쓰면 그 URL을
  프록시의 upstream으로 **체인**하고, 파싱 불가/이상 구성이면 배선을 건너뛴다
  (신경 안 쓰게 ≠ 몰래 망가뜨리게).
- **역-fail-open 방어 3중**: ① launchd KeepAlive 재기동 ② 프록시 자체가
  단순-무의존이라 죽을 이유가 적음(신규 의존성 0 유지) ③ 헬스 워치독 —
  프록시 비응답 N초 지속 시 settings.json의 env 오버라이드를 제거하고
  기억 캡처만 포기 (제품이 죽는 것보다 기억이 굶는 게 싸다). 복구 시 재기입.
- 도그푸드 go-live는 워치독 완성 후 (자기 세션을 실험대에 올리는 순서).

## 2. 아키텍처 이동

| 층 | 종전 | 프록시-네이티브 |
|---|---|---|
| L0 원료 | CC 트랜스크립트 (클라이언트 종속) | **프록시 스트림** (도구 불문 균일) — CC 훅은 폴백 |
| 세션/턴 | CC session_id 공짜 | **재구성 필요**: 요청마다 전체 이력이 오므로 연속 요청의 delta-diff로 턴 경계 복원 + system 지문·metadata로 세션 동일성 (Tencent turnSeq 대응물) |
| 벌크 추출 | 에이전트 판단 (add_memory) — 기아 실측 | **대역-외 추출 게이트**가 스트림에서 (extraction-gate 패턴). add_memory는 "명시 저장 요청" 전용으로 축소 |
| 채굴기 급식 | CC jsonl 파싱 (mine_pairs v0) | 프록시 JSONL — 크로스툴, 서브에이전트 트래픽 포함 |
| 주입 | 훅 (유지) | v2에서만 프록시 주입 검토 — **프롬프트 캐시 안전 경계** 설계가 선행 조건 |

## 3. 프라이버시 재계약 (스트림은 시스템에서 가장 민감한 인공물)

- 스트림은 로컬 전용(`~/.forget/proxy/stream/`), 자격 헤더 무저장(테스트로 강제).
- **원료 TTL**: 원시 스트림은 짧게 살고 (기본 14일 — 리플레이 반감기와 정렬),
  증류물(기억·훈련쌍·러닝북)만 영속. "다 기록하되 다 남기지는 않는다."
- E2EE 로드맵과의 접점: 스트림 at-rest 암호화가 vault 설계의 첫 실적용 대상.

## 3.5 주입 재직조 (2026-08-12 오후, 정훈 발제 "훅 말고 자동·동적 주입" → 공동 설계)

프록시 주입의 두 난제(캐시 붕괴, 턴 간 증발)를 한 수로 푼다: **프록시가
정본 트랜스크립트를 소유한다.** 세션별 주입 원장을 갖고, 매 요청마다 과거
주입을 원위치에 바이트-동일 재삽입(캐시 접두사 보존) 후 새 턴만 게이트 판정.

- 캐시: 훅과 동등 (접두사 불변, 증분 캐시 성장)
- 영속: 회상이 모델 컨텍스트에서 사라지지 않음
- **훅 대비 우위**: 게이트가 현재 프롬프트가 아니라 **전체 대화**를 조건으로
  삼음 — 대화-조건부 회상 (직전 도구 실패 시 기어 상승 등, c40 신호의 일반화)
- 값 1 — 투명성: 트랜스크립트 가시성 상실 → 주입 원장 + `forget recalls`
  CLI로 대체 이행, helped/noise 라벨도 원장 주소로 이동
- 값 2 — 분류: 세션 지문으로 대화형 메인 스레드에만 주입 (서브에이전트·배치
  오염 금지)
- 전제 = #8 세션 재구성기 (지문·delta-diff가 주입 원장의 키)
- 종착: CC 훅도 은퇴 가능 — 주입 엔진 단일화. 3채널 최종형 = 관찰·푸시·풀
  모두 프록시+MCP로 수렴, 훅은 이행기 호환층

## 3.6 진행-중 회상 (2026-08-12, 정훈 발제 "인간은 대부분 자동이잖아")

턴 경계 주입의 갭: 생각이 진행되며 새 연상 단서가 나타나도 다음 턴까지
장기기억이 닫혀 있다. 세 지평 —
1. **도구-결과 동승 (즉시 구현 가능)**: 에이전트 루프의 "생성 중" 실체는 도구
   호출 사이 — PostToolUse 훅/프록시 재직조가 도구 결과 내용(에러·파일)을
   단서로 회상을 계산해 결과에 동봉. 트리거 = 사용자 프롬프트가 아니라
   진행 중인 사고의 내용물. 게이트·예산 규율은 턴 주입과 동일 적용 (도배 금지).
2. **로컬 서빙 일시정지-주입**: 우리가 서빙을 소유한 경로(벤치·로컬 어댑터
   모델)에서 생성 스트림 신호(엔티티·불확실성)로 pause→retrieve→resume.
3. **L4**: kNN-LM 보간·교차-어텐션·신경 캐시 — 주입 개념 소멸. 문헌상
   프로덕션 실증 부재 (2026-08 조사) — 연구 트랙.

## 4. 실행 순서

1. **#7 zero-config 배선**: launchd plist + connect 배선 + 기존 URL 체인 + 워치독
2. **#8 스트림 세션 재구성기**: delta-diff 턴 복원 + 세션 지문 → 채굴기·에피소드
   급식 전환 (mine_pairs가 스트림을 1급 입력으로)
3. 도그푸드 go-live (워치독 후) → 2주 크럭스 기간의 훈련 데이터가 스트림에서 나옴
4. v2: OpenAI-호환 핸들러 (Codex CLI 등), 캐시-안전 프록시 주입 검토
