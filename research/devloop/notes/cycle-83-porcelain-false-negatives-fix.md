# 사이클 83 — 관측 38 처치: 영토 검사의 눈에서 거짓 음성 2종 제거

2026-08-09 · 일반 사이클(83%10=3·83%5=3) · 계기 전용(제품 코드 무변경) · 무게이트(c73 재분류 선례)

## 무엇을

c82가 기록만 하고 떠난 관측 38 — `porcelain_changed_paths`의 "변경 있음→'깨끗함'" 방향
거짓 음성 2종 — 을 frictions.md 수용 기준 ② 그대로 집행했다.

1. **리네임/카피 행** (`R  old -> new`): 상태 코드에 R/C가 있는 행만 ` -> `에서 양쪽
   경로로 가른다(`_split_rename_columns`). old는 디스크에 없어 하류 exists에서 걸러지고
   (D 행과 같은 취급), new가 mtime 검사에 들어간다 — 리네임된 미커밋 WIP가 영토 검사에
   보인다. 인용된 old(`"a -> b.md" -> c.md`)는 닫는 인용부호를 스캔해 인용 속 화살표를
   경로의 일부로 지킨다. 상태 코드 무-R/C 행은 가르지 않는다 — 화살표를 품은 평범한
   파일명이 리네임으로 오인되는 **역방향** 오류를 함께 막았다.
2. **quotepath 8진 이스케이프** (`"\355\225\234…"`): 인용 경로를 C 스타일로 디코드한다
   (`_dequote_c_style`). 바이트로 모은 뒤 **surrogateescape**로 복원 — 비UTF-8 파일명도
   os.path.exists가 그대로 통과하는 유일한 복원이다. strict는 죽고, replace는 디스크에
   없는 다른 문자열을 만들어 **고치려던 바로 그 방향의 거짓 음성을 재생산**한다.
   (판정: os.fsencode 왕복으로 원본 바이트 보존을 테스트가 단언한다.)

## 왜 지금

- 방향이 위험한 쪽이다: 절차 2(영토 규약)가 막으려는 바로 그 상황 — 타 세션 WIP가
  있는데 "깨끗함"으로 읽고 코드 사이클 진입 — 에서 침묵한다. 이 저장소는 워크스페이스
  디렉터리명부터 한국어라 ②는 가설이 아니라 실질 노출이었다(관측 38 문면).
- 가장 작은 가치 단위: 당일 판정 가능(울리라고 둔 종 2건을 정상 동작 단언으로 교체),
  게이트 불요, 제품 코드 무접촉.

## 정직 한계

- porcelain v1은 무인용 ASCII 경로 속 ` -> `를 진짜 구분자와 가릴 수 없다(양쪽 다 화살표를
  품으면 어느 쪽으로 갈라도 모호). 근본 처치는 `-z` NUL 형식 전환 — 미집행. 발생 조건이
  인위적(파일명에 리터럴 ` -> `)이라 부채로 등재하지 않고, 관측 38 재발 검사 ③(part_a
  총계 대 육안 대조)이 커버한다.
- 호출측을 `-c core.quotepath=off`로 바꾸는 대안은 기각 — 파서를 고치면 호출 구성과
  무관하게 안전하고, 순수 함수라 테스트가 문다. 호출측 변경은 파서가 못 고치는 것이
  없어진 지금 불필요한 이중 처치다.
