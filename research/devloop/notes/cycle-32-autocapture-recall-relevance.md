# 사이클 32 — marginal 자동캡처 회상의 주제 관련성 내용 실측 (2026-08-03)

코드 사이클 금지) + 정훈의 uv.lock 처분 응답 부재 → 관찰·측정 폴백. 선택 =
`get_task_state` next_actions[1] 잔여 후보 = **사이클 29 잔여 관측 2 집행**.

## 검정 대상 (사이클 29가 명시 연기한 잔여)

사이클 29는 crowd-out 가설을 반증하면서 **잔여 관측 2**를 남겼다:

> post-flood 회상 **출력의 24.3%(4061건 선택 인스턴스)가 여전히 자동캡처**, 선택 임계에
> 밀착(sel_median 0.4462). "crowd-out"은 아니나 회상 슬롯의 ~1/4를 저신뢰 자동캡처가
> 점유 = 출력 조성의 실질적 희석. 그 marginal 자동캡처가 **주제 관련인지는 점수만으로
> 판별 불가(내용 읽기/관련성 라벨 필요 — 향후 측정)**.

이 사이클이 그 **내용 읽기**를 수행한다.

## 방법 ($0·로컬·read-only mode=ro, 스크립트 `scripts/autocapture_recall_relevance.py`)

핵심 데이터 사실(이 사이클 발견): 회상 **쿼리는 주제형이 아니다** — 전부
`"session startup in <cwd> — active tasks, open loops, recent decisions"` 형태의
세션 복원 쿼리다(post-flood 79개 distinct 쿼리 중 devloop 워크스페이스 startup이
2325/2406 지배). 그리고 자동캡처 메모리는 전부 **세션 요약**이며 metadata.transcript_path /
본문 "전문: /Users/…" 꼬리에 **출처 프로젝트를 담는다**. Claude가 출처를 트랜스크립트
디렉터리명에 인코딩:
- `-Users-junghunkim-orca-workspaces-forget----------------` = devloop 워크스페이스
- `-Users-junghunkim--PARA-0-Inbox-DILABv2` = DILAB 하드웨어 프로젝트

→ marginal 자동캡처의 **주제 관련성을 조작화**(게임내성: 출처 파싱은 점수와 독립):
- **same_context**: 캡처된 세션의 출처 프로젝트 == 쿼리 cwd 프로젝트
- **off_context**: 교차 프로젝트 스코프 누수 (다른 프로젝트 세션이 이 cwd 복원 쿼리에 표면화)

이는 프록시이며 **상위 6개(=선택 인스턴스의 100%)를 직접 내용 읽기로 검증**했다.
"same_context == 유용"이라는 주장이 아니라, "cwd X의 작업 컨텍스트 복원" 쿼리에 대한
가장 날카로운 내용 신호다.

| same-context (출처==쿼리 cwd) | **4061 (100.0%)** |
| off-context (교차 프로젝트 누수) | **0 (0.0%)** |
| marginal 밴드 [0.40,0.50) 점유 | 4061/4061 (선택된 자동캡처는 전부 marginal, min 0.4420·med 0.4462·max 0.4555) |

회상에 도달하는 것은 오직 devloop 워크스페이스 쿼리 + 그 자신의 devloop 세션들뿐.

## 결과 2 — 메커니즘 정정: 셀렉터 판별이 아니라 **검색-단 경로토큰 매칭**

devloop-startup 트레이스에서 off-context 자동캡처는 **후보에조차 오르지 않는다**
(candidate off=0). 클린한 출력은 셀렉터가 off-context를 강등해서가 아니라 **검색 단계가
애초에 후보로 안 올려서**다. 원인: 쿼리가 cwd 경로를 담고("…in /Users/…/forget/내-…"),
same-project 세션 요약도 본문에 같은 경로("전문: /Users/…/forget/…")를 담아 → 긴 경로
토큰이 임베딩/어휘 유사도를 구동. 교차 프로젝트 요약은 경로가 달라 미검색.

**대칭 관찰(정직)**: 이건 사이클 18이 F2의 원인으로 확정한 바로 그 메커니즘
(C1: phrase/부분문자열 매칭 × 고정 프롬프트)이다 — 다만 여기선 매칭 토큰(cwd 경로)이
곧 관련성 축이라 **관련성에 유리하게** 작동한다. 메커니즘은 관련성-중립: 매칭 토큰이
관련성 축과 일치하면(startup 쿼리 ⊃ cwd 경로) 돕고, 어긋나면(주제형 쿼리에 junk 한국어
토큰이 매칭) 해친다. F2와 이 사이클은 **같은 기전의 두 부호**다.

## 결과 3 — same-context ≠ 정보성: 잔여의 실체는 **중복·저정보 자기캡처**

회상 발자국(footprint):

| 척도 | 값 |
|---|---|
| 스토어의 자동캡처 메모리 | 2531 |
| 회상 후보로 한 번이라도 오른 것 | **15 (0.6%)** |
| 한 번이라도 선택된 것 | **6 (0.24%)** |
| 상위 3개 메모리의 선택 지분 | **3766/4061 = 92.7%** (극단적 집중) |

즉 사이클 29의 "출력의 24.3%"는 **폭(breadth)이 아니라 6개 메모리의 반복**이다.
2531건 홍수의 **99.4%(2516건)는 회상에 후보로도 안 뜨는 사문(死文)**. 상위 6개 전부
devloop 자신의 세션 캡처 요약이며, 내용 직독 결과:

- `ddbd5754` (×1198, 전체 선택의 29%): **1 user·1 assistant 메시지 퇴화 세션** 캡처 —
  본문이 devloop 상시 프롬프트 에코뿐, 복원가치 ≈0.
- `7fb2959c` (×146): 동일하게 1·1 퇴화 세션. (두 퇴화 캡처 합 ≈ 33% of 선택)
- `c5009e9c` (×1355): 실질 세션(47 asst)이나 요약 본문 = 상시 프롬프트 에코(저변별).
- `a9ad4087` (×1213): 실질 세션(62 asst)이고 요약 본문이 **실제 유용한 발견**
  (search_memories top_k/limit 파라미터 조용한 무시 실측) — 6개 중 유일한 고신호.
- `a7cdf8e4` (×141), `3e7daea6` (×8): same-context 실질 세션.

**근본 원인**: devloop 세션들은 전부 **동일한 상시 프롬프트로 시작**하므로 세션 캡처
요약("최근 사용자 발화"를 본문으로 씀)이 서로 **근사 중복**이 되고, 그래서 같은 몇 개가
startup 쿼리의 cwd 경로 토큰에 항상 매칭돼 반복 표면화된다. 이 역시 사이클 18 C1
(고정 devloop 프롬프트)의 발현.

## 판정

1. **주제 관련성(스코프): PASS.** marginal 24.3%는 **누수 0, 100% same-working-context**.
   사이클 28의 "홍수가 F2/관련성 악화" 우려는 스코프 축에서도 반증 — 교차 프로젝트
   junk가 회상 출력에 표면화되지 않는다. 사이클 29의 crowd-out 반증에 이어 **관련성 반증**.
2. **그러나 same-context ≠ 정보성.** 잔여 희석의 실체는 off-topic이 아니라 **중복·저정보**:
   6개 same-context 요약의 반복, 그 중 ≥33%(두 퇴화 캡처)는 복원가치 ≈0인 빈 세션 에코.
   "저신뢰 자동캡처가 슬롯의 1/4 점유"는 참이나, 해악은 **무관함이 아니라 중복성**이다.
3. **메커니즘 통합.** 클린 스코프는 검색-단 cwd-경로 토큰 매칭(셀렉터 판별 아님)의 부산물이며,
   이는 F2의 원인 기전(C1)의 유리한 부호다. 자동캡처 홍수는 회상에 99.4% 사문 — 압축
   헤드라인(스토어 총계)엔 부풀지만 **회상 발자국은 극소·집중·자기참조**.

## 정직성 캐비앗

- 관련성은 **same-vs-off-context 프록시**로 조작화됨. 유효성은 상위 6개(=선택의 100%)의
  직접 내용 읽기로 검증됨 — 프록시 단독 주장 아님. 단 "same-context==유용"은 주장 안 함
  (판정 2가 정확히 그 반례).
- "off-context 0"은 **후보-검색 사실**이지 셀렉터-판별 사실이 아니다(셀렉터는 off-context를
  거절할 기회조차 없음 — 검색이 안 올림). 스마트한 셀렉터와 다른 기전.
- post-flood 단일-스케일 regime(사이클 29와 동일 reembed 교란). pre/post 델타 귀속 불가.
- 발견은 사실상 **devloop 자기루프의 회상**에 관한 것(쿼리 2325/2406 = devloop cwd). 일반
  회상으로 일반화 불가 — 비-devloop 쿼리에선 자동캡처가 후보에도 없음.
- 경로: context_traces는 startup/autopilot 조립 중심(사이클 29 캐비앗 승계). turnrecall과
  경로별 분해는 미측정.
