## 6. 사이클 내 자기반증 — "전량 슬롯"은 없었다 (220자였다)

§5의 처치를 집행한 직후 계측기를 재실행했다. 세 기준은 즉시 충족됐다 — 그리고 네 번째가
**내 서술을 반증했다.**

```
current=devloop                                     ← (a) 소유 이전 성공
devloop-self[0]  delivered 75/75                    ← (d) 90자 파이프 무손실
step0 규약 캡슐 도달  3/3  (c46 1/3 · c47 초측 1/3)   ← (c) 성공
devloop[0]       delivered 218/743                  ← (b) 실패. "전량"이 아니었다
```

원인은 두 번째 컴파일 상수다:

```
forget/store.py HEAD:9411   f"현재 목표: {_autopilot_short_text(capsule.get('goal'), 240)}"
forget/store.py HEAD:9412   f"현재 상태: {_autopilot_short_text(capsule.get('status'), 120)}"
forget/store.py HEAD:9413   f"다음 행동: {_autopilot_short_text(next_action.get('action'), 220)}"
```

**정정된 결론.** 캡슐의 step 0 관은 "전량 1건 + 90자 × 2"가 아니라 **소유자가 다른 상수 4칸**이다:

| 슬롯 | 상수 | 소유자 |
|---|---|---|
| 현재 목표 | **240자** | `summary` (최신 쓰기 태스크) |
| 현재 상태 | 120자 | `status` |
| 다음 행동 | **220자** | `next_actions[0]` (최신 쓰기 태스크) |
| 병행 트랙 | **90자 × 2** | 그 다음 2개 태스크의 `next_actions[0]` |

합 640자. 루프의 step 0 지시는 **이 네 칸에 나눠 실어야 한다.** 한 칸에 다 넣을 수 없다.

**재처치와 최종 실측.** `devloop[0]`을 220자 예산에 맞춰 212자로 다시 쓰고(밀려난 상세는 `[1]`로
보존) 재실행:

```
current=devloop                     devloop[0]      delivered 212/212   ← 전량
                                    devloop-self[0] delivered  75/75    ← 전량
step0 규약 캡슐 도달  3/3            stage_A_reach   2/21               ← 비-예측대로 항목 수 불변
capsule_text 1,285자 / 예산 1,600   truncated=False
```

**(ii)가 도착한 경로는 '다음 행동'이 아니었다 — 정직 기재.** 규약 (ii)(미커밋 mtime 검사)는
220자 안에 못 들어갔고, **`summary` 앞부분에 적힌 덕에 '현재 목표' 슬롯(240자)을 타고 도착했다.**
즉 요약도 전달 채널이며, 이것은 계획된 설계가 아니라 사후에 확인된 우연이다. c48은 이를
의도적으로 쓸 수 있다(요약 앞 240자 = 네 번째 파이프).

**이 반증이 이 사이클의 가장 정직한 부분이다.** §1은 c46의 "즉시 적용했다"는 자기보고를 의심해
재실측한 결과였다. §6은 **같은 의심을 내 자신의 처치 서술에 적용한 결과**이며, 나 역시 틀렸다.
`[:90]`을 찾고서 "나머지는 무제한"이라고 **추론했고 확인하지 않았다** — 처치를 집행하고
재측정하지 않았다면 이 노트는 틀린 상수를 다음 손에게 물려줬을 것이다.

## 7. 쓰기 사고 1건 — malformed `record_task_state` 2회 (c40·c41에 이은 3회차)

절차 5의 첫 두 `record_task_state` 호출이 malformed로 나갔다: `next_actions` 배열이 `summary`
문자열로 흡수돼 **응답의 `next_actions`가 빈 배열**로 기록됐다. 긴 `summary`와 배열 파라미터를
MCP 도구 호출로 함께 보낼 때 재현된다.

**적발한 것은 그림자 규약이다.** `devloop.next_actions`의 `[호출측 자기규율]` 항목이
*"쓰기 후 응답의 next_actions가 비어 있지 않은지 확인하고 비었으면 즉시 정정 쓰기"*를 지시하고
있었다(c40·c41 전례). 그 규약이 없었다면 두 태스크 모두 `next_actions` 0건으로 c48을 맞았을
것이다 — **장부가 자기를 잃는 사고**이고, c44가 진단한 "절차 5에 도달 못 한 사이클"의 사촌이다.

**우회로(c47 확립).** 지시서 절차 0이 이미 명시한 HTTP 경로
(`localhost:8000/mcp/forget/http/junghunkim`, `tools/call`)로 JSON을 직접 구성하면 정상 기록된다.
조회용으로만 적혀 있던 경로가 **쓰기 폴백**으로도 유효함을 이 사이클이 확인했다.

## 부기 — 제품 함의 (루프 밖)

이 결함은 devloop만의 것이 아니다. `[:90]`·`[:2]`는 모든 forget 유저의 캡슐에 붙는다.
**활성 태스크가 3개를 넘으면 4번째부터는 존재 자체가 캡슐에서 사라지고**, 병행 트랙에 남은
2건도 90자에서 어절 중간이 잘린다. c46이 "기억을 많이 쌓은 유저일수록 전달 비율이 낮아진다"고
적은 것에 축을 하나 더한다: **태스크를 많이 굴리는 유저일수록 조용히 탈락한다.**
그리고 어느 태스크가 살아남는지는 유저가 마지막으로 무엇을 썼는지에 달려 있다 — 중요도가 아니라.
