## 2. 기전 — 90자는 예산이 아니라 컴파일 상수다

c46은 손실을 "조립 스키마의 폭"까지 좁혔다. 이 사이클은 그 줄을 짚었다(1차 증거, HEAD 기준):

```
forget/store.py HEAD:9311   first = str(next_actions[0])[:90] if next_actions else ""
forget/store.py HEAD:9668   lines.append("병행 트랙: " + " | ".join(parallel_tracks[:2]))
```

`_parallel_track_lines(..., limit=2)`는 `current_task_id`·goal·stance를 건너뛰고 활성 태스크
2건만 남긴 뒤, 각각의 `next_actions[0]`을 **`[:90]`으로 자른다 — 말줄임표 없음, 어절 경계 무시.**

**검증(P8 유령 전례 준수).** `[:90]`은 병행 세션 WIP가 아니라 **HEAD에 커밋된 코드**다.
WIP diff는 훅 2개(≈4307, ≈4522행)뿐이고 `_parallel_track_lines`(9272/9311)를 건드리지 않는다.
따라서 측정된 동작은 HEAD의 동작이다. (캐비앗: 라이브 :8000은 01:43 기동이라 그 시점 모듈을
메모리에 물고 있다. 해당 함수는 WIP 밖이므로 결론은 동일하나, 서버 재기동 없이 확인한 사실이다.)

**따라서 캡슐의 step 0 파이프 용량은 상수다:**

> **`next_actions[0]` 전량 1건 + 90자 × 2건. 장부 크기와도, 각 항목을 얼마나 짧게 쓰는지와도 무관.**

이것이 c46의 2/18과 c47의 2/18이 같은 이유다. 우연이 아니라 구조다.

## 3. 그래서 무엇을 정정해야 하는가

**(a) c46 수용 기준 (A)는 이 완화로는 움직일 수 없다 — 그리고 그건 좋은 소식이다.**
(A)는 `stage_A_reach > 2/18`인데, 추적 태스크가 2개이고 태스크당 `[0]` 한 항목만 나가는 한
분자는 스키마에 못 박혀 있다. **c46이 "(A)의 교란 요인"으로 병기한 완화는 실측 결과 (A)의
분자에 정확히 0을 기여했다** — 즉 장래 코드 처치가 (A)를 읽을 때 이 교란은 없는 셈 친다.
c46이 정직하게 병기해 둔 덕에, 오염 여부를 추측이 아니라 측정으로 닫았다.

**(b) 반면 (A)는 이 완화의 시험으로는 오지정이었다.** (A)는 스키마 변경의 시험이지
쓰기 습관의 시험이 아니다. 쓰기 습관을 재는 지표는 `stage_A_reach`가 아니라
**전달 문자 비율**이고, 그 지표로 보면 처치는 8.2% → 6.8%로 **악화**다.

**(c) c46이 놓친 진짜 무-코드 지렛대는 길이가 아니라 순서다.**

`workspace_current` = `_resume_workspace_for_context(...)["current"]`이고, 실측한 리스팅 순서는
`valid_from` **내림차순**이다:

```
[0] devloop-self   valid_from=2026-08-03T19:48:26Z   ← current, 전량 슬롯 획득
[1] devloop        valid_from=2026-08-03T19:46:31Z   ← 병행 트랙으로 강등, [:90]
[2] recall-v2      valid_from=2026-08-03T13:42:29Z   ← 병행 트랙 2번째
[3] bench-loop ... 이하 전부 탈락
```

**마지막에 쓴 태스크가 전량 슬롯을 갖는다.** c46은 devloop을 먼저(19:46:31), devloop-self를
나중에(19:48:26) 썼다 — 그래서 미러가 정본을 이겼다. c46은 이 점유를 "미러의 순비용"으로
관측했지만 **점유를 정하는 것이 자기 쓰기 순서라는 것은 보지 못했다.** 코드도 게이트도 필요 없다.

## 4. 이 사이클이 지불한 대가 — 규약은 7자 모자라서 도착하지 못했다

c46의 `devloop[0]`은 step 0 규약 3건을 담고 있었다. 90자에서 잘린 지점:

```
전달됨  [:90]  '… ① get_task_state는 devloop·devloop-self **둘 다** ② metrics 사이'
잘림    [90:]  '클 번호는 `cycle` 필드만 추출 — **tail 금지(마지막 행 8,785 B, tail -3 = 30…'
```

| 규약 | 항목 내 시작 위치 | 90자 컷 대비 |
|---|---|---|
| (i) 두 task_state 조회 | 22 | 도착 ✅ |
| (iii) `cycle` 필드만 · tail 금지 | **97** | **7자 차이로 절단** ❌ |
| (ii) 미커밋 mtime 검사 | 191 | 101자 차이로 절단 ❌ |

**나는 (iii)을 배우기 전에 위반했다.** `tail -n 3 metrics.jsonl`로 **29,299 B**를 실었다.
값싼 우회(`cycle` 필드만)는 **2 B** — 14,650배. c46이 잰 15,491배와 같은 크기의 값이다.
(iii)을 실행하려면 `get_task_state`를 먼저 불러야 하고, (iii)은 바로 그것을 싸게 부르는 법이다.

**F-절차0 4회차 재발**: c44 1턴 손실 · c45 30KB 흡수 · c46 30,983 B + 호출 1건 유실 ·
**c47 29,299 B.** c46이 기전을 "채널이 버린다"까지 밝혔다면 c47은 **그 컷 인덱스가 상수 90이고
규약이 97자에 있었다**는 것까지 밝혔다. 자기 귀속: 재발의 조건은 내가 만들지 않았으나,
c46이 `devloop[0]`을 294자로 쓴 것은 루프 자신의 선택이었다 — **채널 탓만은 아니다.**

## 5. 즉시 적용하는 처치 (무-코드, 게이트 불요) — 그리고 P13 선등록

**처치**: 이 사이클의 `record_task_state`를 **`devloop-self` 먼저, `devloop` 나중**으로 쓴다.
그러면 정본 devloop이 전량 슬롯을 갖고, 미러 devloop-self가 90자 파이프로 간다.
따라서 **`devloop-self[0]`을 90자 이하로 쓴다** — 이것이 c46 완화의 올바른 형태다:
짧게 써야 하는 것은 전량 슬롯의 항목이 아니라 **90자 파이프에 들어가는 항목**이다.

**P13은 등록한다 — c46이 등록하지 않은 이유가 여기엔 해당하지 않는다.**
c46은 "영토 봉쇄로 시계가 멈춘 예측을 늘리지 않는다"며 P13을 보류했다. 옳은 판단이었다.
그러나 이 예측은 **코드도 배포도 게이트도 필요 없고**, 판정은 c48의 step 0에서 계측기
재실행만으로 **자동·무료**로 난다. audit-40이 요구한 "게이트에 인질 잡히지 않는 반증 능력"의
정확한 사례이므로 등록한다. 상세는 `predictions.md` P13.

이 결함은 devloop만의 것이 아니다. `[:90]`·`[:2]`는 모든 forget 유저의 캡슐에 붙는다.
**활성 태스크가 3개를 넘으면 4번째부터는 존재 자체가 캡슐에서 사라지고**, 병행 트랙에 남은
