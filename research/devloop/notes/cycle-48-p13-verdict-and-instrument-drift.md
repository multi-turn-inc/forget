## 4. 이 사이클이 발견한 것 — 규약 (ii)는 이 체크아웃에서 거짓 음성 기계였다

step 0에서 규약 (ii)("HEAD보다 새로운 미커밋 파일 mtime 검사")를 집행하며 이렇게 썼다:

```
find . -newer .git/HEAD -type f ... 2>/dev/null     → 0건
```

0건을 보고 "죽은 선행 사이클 유산 없음"으로 넘어갈 뻔했다. **틀렸다.**
이 체크아웃은 git worktree이므로 `.git`은 디렉터리가 아니라 **포인터 파일**이다:

```
.git kind=file(worktree pointer)   gitdir: /Users/junghunkim/Documents/forget/.git/worktrees/내-프롬프트를-공유하기-싫어
naive_ref_exists=False   ref=<repo>/.git/HEAD
safe_ref_exists=True     ref=<common>/.git/worktrees/<name>/HEAD
```

참조 파일이 없으면 `find -newer`는 실패하고, `2>/dev/null`이 그 실패를 삼킨다.
**즉 이 명령은 저장소 상태와 무관하게 항상 "깨끗함"을 답한다.** 검사가 아니라 거짓 음성 기계다.

커밋 시각 기준으로 제대로 재면(`c48_step0_check.py` A절):

```
head_commit_epoch=1785788749  (2026-08-04 05:25:49)
uncommitted_paths_newer_than_HEAD=3
  +  478s  research/devloop/notes/cycle-47-slot-order.md
  +  420s  research/devloop/scripts/c46_capsule_reach.py
  + 1944s  research/devloop/scripts/c48_step0_check.py   ← 이 사이클 자신의 산출물
```

**검사가 실제로 잡은 것 (앞의 2건).** c47은 05:25:49에 커밋(절차 5)한 **뒤에도** 작업을 계속해
05:32:49에 계측기 니들을 확장하고 05:33:47에 노트 §6(자기반증 76행)을 덧붙였으며 —
**다시 커밋하지 않았다.** c47이 스스로 "이 사이클의 가장 정직한 부분"이라 부른 §6은
장부(task state)에는 있고 git에는 없었다. c45가 "규칙의 유일 사본이 DB에 있다"고 적은 것의
정확한 거울상이다. **이 사이클이 커밋해 해소한다**(§6 아래).

**자기 귀속.** 규약 (ii)의 문장은 도구를 지정하지 않았고("git status + HEAD보다 새 미커밋 mtime"),
`find -newer .git/HEAD`는 **내가** 고른 구현이다. 규약은 도착했다 — 도구가 도착하지 않았다.
그리고 잘못된 구현의 실패 방향이 하필 "이상 없음"이었다.
