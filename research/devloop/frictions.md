# 마찰 분류체계 — 루프의 검증 데이터

설계는 예측하고 방지하는 실패로 검증된다. 모든 필드노트는 여기 유형에 귀속되고,
설계 변경의 성패는 유형별 재발률로 판정한다.

| 유형 | 정의 | 사례 | 상태 |
|---|---|---|---|
| F1 신선도 | 유동층이 완만층처럼 굳음 — stale 상태가 현재로 제시됨 | 필드노트 #1: 이틀 전 박자를 "현재 목표"로 (2026-07-31) | 코드 해소(사이클 2) — 캡슐에 나이 병기 + 24h 초과 stale 경고. 배포(0.3.5) 후 재발률로 판정 |
| F2 관련성 | 회상 선택이 턴 주제 대신 활성 상태를 우선함 | 필드노트 #2: 무관 Quant 태스크 반복 노출 (2026-07-31); 사이클 3 세션 시작 회상에도 heartbeat·stance 노출 재확인; 사이클 4 세션 회상에도 재확인 — 단 라이브가 0.3.4(구코드)라 코드 해소의 반증이 아니라 미배포의 증거 | 코드 해소(사이클 3) — task_state 검색의 무조건 +0.08 활성 보정 제거, 활성도는 recency로만. 판정은 P3(사이클 8까지 재발률) |

| F4 스코프 오배송 | 다른 스코프에 속할 데이터가 canonical 풀에 배송되거나, 지표가 스코프를 무시하고 합산함 | 사이클 8 센서스: demo/livetest/offreco ~339건이 라이브 DB에 동거(유입 7/9~7/27 반복), heartbeat 활력 지표 "827 기억"은 전 DB 총계 — 픽스처가 수치의 ~39% (2026-07-31, notes/cycle-8-memory-census.md) | 관찰 등재. 수용 기준: canonical 외 user_id 신규 유입 0건/주 + 스코프 총계 지표는 스코프 명시. 정리(삭제)는 게이트 대상. codex-dual-memory-write-path와 동형 |
| F5 침묵 잊음 | 잊음(탈락·병합·무추출) 결정이 감사 추적 없이 일어남 — 게이트 로그가 잊음의 극소수만 커버 | 사이클 7 감사: 30일 ADD 34,530건 → 기억 517개, 게이트 로그 거부 1건. 과압축 감사의 분모가 전수가 아니라 표본 1 (2026-07-31, notes/cycle-7-gate-audit-baseline.md) | 관찰 등재. 수용 기준: ADD 유입 = 저장+병합+거부(로그)+무추출(계수) 항등식 성립. #25 오류 구조화·#24 영수증과 인접 |
| F6 미검증 보존 주장 | "저장/보존했다"가 커밋·영수증 등 내구 증거 없이 선언됨 | 사이클 6: reply-to-sol이 "저장소에 보존했고"라 썼으나 feedback/ 두 파일은 untracked — 디스크에만 존재 (2026-07-31) | 관찰 등재. 해소 경로는 #24 쓰기 영수증(제품측) + 수확 단계의 커밋 확인(루프측). Sol P0-3과 동형 |
