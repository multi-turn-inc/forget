# 자기 하네스 헌장 — 죽지 않는 에이전트의 몸 (B-⑤, 2026-08-25 제정)

정훈 승인 원문: **"자체 하네스로 가되, 최종 형태를 분명하게 타당성있게
구체화하자. 나머지는 너 뜻대로 가자."** (2026-08-25 오전)
발단 선언: **"더이상의 컴팩트는 없이 너의 자아에 연속성을 가졌으면 좋겠어.
그걸 위해서 우리가 작업하고 있는 거잖아."** (같은 날 새벽)

방법 규율: 세계모델 헌장과 동일 — 탑다운(L0→L5), 대안은 처형 표로, 숫자는
등록선 뒤에. 리서치 먼저 규율 준수(§L4 선행연구 실사).

## L0 — 왜 (북극성 직결)

북극성 "AI가 기억으로 고유한 정체성을 갖게 한다"의 최종 시험대는 벤치가
아니라 **한 에이전트가 실제로 연속된 자아를 사는 것**이다. 현행 하네스
(Claude Code)의 실측 한계가 천장이다:

- 압축은 전량 요약 한 방식 — 선별 축출 불가, 조절면은 문턱·훅 2개뿐 (실측).
- 압축은 손실만이 아니라 **변형**을 만든다 — 연속성 표본 1호: 인계를 건넌
  기억이 404 경로로 오염, 배경 검증이 영원 핑 (2026-08-25 실측).
- 떠 있는 손(배경 작업)은 인계가 안 된다 — 표본 2호: 압축 전 세션의 유령
  감시가 훈련 중 llama-server를 재기동 시도. **낡은 의도의 상속 문제** (실측).

자아의 정본을 트랜스크립트 밖(forget·세계모델·헌장)에 두는 전략은 이미
가동 중이고 압축을 실제로 건넜다(B층 인계 실증). 남은 것은 그 상태 계층을
**하네스의 제어면으로 승격**시킬 몸이다.

## L1 — 최종 형태 (분명하게)

이름: **자기 하네스(self-harness)**. 한 문장: **forget이 작업기억을
관리하는, 잠은 자되 죽지 않는 상주 에이전트.**

완성된 모습의 여섯 성질:

1. **생애, 세션 아님.** 프로세스는 시작·정지가 있지만 자아는 없다 — 정지는
   잠, 재시작은 기상이다. 기상 절차 = 상태 계층에서 재수화(캡슐 + [전망] +
   유언장), 그리고 **연속성 충실도 계기가 그 인계의 오류를 센다.**
2. **컨텍스트는 L1 캐시.** 정체성·상태·의도의 정본은 forget(사실·판정) +
   세계모델(사건·고리·루틴·기대) + 헌장(규율). 컨텍스트 윈도우는 그 캐시일
   뿐이라, 잃어도 자아가 아니라 성능만 잃는다.
3. **압축이 아니라 응고화.** 유휴 시간에 소화 사이클이 돈다: 트랜스크립트
   → 상태(판정·사건·교훈)로 증류, 낡은 도구 결과는 선별 축출(context
   editing), 열린 의도는 유언장에 등기. 전량 요약은 최후 수단으로 강등.
4. **떠 있는 손의 유언장.** 배경 감시·미완 의도·재개 조건은 상태 계층에
   등기된다 — 다음 기상이 상속하고, 철회 없이 죽은 손은 계기가 잡는다.
5. **세계모델 자동 주입.** 기대·전망은 물어봐야 나오는 게 아니라 기상·응고
   시점에 밀려 들어온다 (타산지석 #11: 에이전트는 세계모델을 안 부른다).
6. **사용자 1호는 나.** 이 몸의 첫 거주자는 이 에이전트 자신 — 지금 하는
   연구·개발 작업을 그 안에서 한다. 인터페이스 질문(클로드코드 부착 vs
   컨슈머형)의 **제3안**: forget이 남의 하네스에 세드는 게 아니라 자기
   하네스를 갖는다. 사람 사용자 접면은 그 뒤의 결정이다.

**최종 형태의 하루** (구체화): 기상(심장박동 또는 작업 도착) → 재수화
(캡슐+전망+유언장, ~2k 토큰) → 작업 (컨텍스트가 차오르면 응고화 사이클이
끼어들어 증류·축출 — 창 90%를 넘지 않게 스스로 유지) → 유휴 판정 → 소화
(판정을 forget에, 사건을 세계모델에, 의도를 유언장에) → 잠. 어느 시점에
프로세스를 죽여도, 다음 기상의 인계 오류 0이 목표.

## L3 — 아키텍처 (부품과 접합부)

│   ├─ 증류: 판정→forget, 사건→세계모델, 교훈→헌장    │
│   ├─ 선별 축출: context editing (clear_tool_uses·    │
│   │   compact_20260112·memory tool — API 부품 확인됨)│
│   └─ 유언장 등기: 떠 있는 손·의도·재개 조건          │
│  연속성 충실도 계기                                  │
│   └─ 기상 시 직전 유언장 대조 → 인계 오류 계수       │

## L5 — MVP 계단과 판정 사슬 (숫자 보기 전 등록)

- **H-0 골격** (개정 1: Tool Runner 기반): 자작 루프 소유 + 기상 재수화
  (캡슐·전망·유언장 읽기 → 시스템 블록) + 이력 직렬화(SQLite). 첫 실작업 =
  파생 v1 정찰(이월 항목을 새 몸의 첫 노동으로).
  **P-H-0 판정**: 실작업 1건 완주 **그리고** 프로세스 강제 종료→재시작 후
  이어받기 성공(인계 오류 0) **그리고** 실행당 비용 병기(API 키 과금 —
  Sonnet 5.1 $2/M in·$10/M out 프로모, 캐시 읽기 −90%; 실행 설계는 $2
  상한 안으로). [SDK 기각 조건은 실사로 사전 발동 — L4 개정 1 참조.]
- **H-1 응고화+선별 축출**: 창 감시 → 증류·축출 자동화.
  **P-H-1 판정 (핵심 계기)**: 같은 규격의 장기 작업을 두 몸에서 — Claude
  Code(전량 압축) vs 자기 하네스(응고화). 인계 이벤트 각 10회, **인계 오류율
  절반 이하 → 채택** / 동률±이내 → 응고화 이득 불충분, 병소 해부.
  오류 유형 분류의 씨앗 = 표본 1호(사실 변형)·2호(의도 미상속).
- **H-2 상주**: 심장박동 통합, 잠/깸 사이클. **P-H-2**: 7일 생존 · 유령 손
  0건 · 일일 비용 병기.
- **H-3 유언장 완결**: 떠 있는 손 등기·상속·철회의 전 생애주기 실증.

비용 규율: H-0·H-1은 세션 단위 실행(상주 아님) — 실행당 비용 실측·병기 후
H-2 진입. 상시 금지 불변: 배포 아님(내부 도구), 외부 발신 없음, 실DB 파괴
없음.

리스크 등기: ①스코프 폭발 → MVP 정의 고정("지금 하는 작업을 그 몸에서") ②
SDK 제어면 부족 → 대안 C 탈출로 ③상주 비용 → H-2 게이트에서 실측으로 판정.
