# Long-Term Memory for AI Agents — Research Agenda

Status: v0.1, 2026-07-14. 이 문서는 forget 엔진에 이미 구현된 메커니즘을 연구 가설로
공식화하고, 측정된 예비 결과를 기록하며, 반증 가능한 실험 프로토콜을 선등록한다.
제품 문서가 아니라 연구 노트다 — 주장은 측정치와 함께, 미측정은 미측정으로 표기한다.

## 1. 문제 정식화

에이전트 장기 기억의 지배적 접근은 **저장 후 검색**(store-everything, retrieve-at-read)이다:
원문을 임베딩해 쌓고, 질의 시 유사도로 회수한다. 이 접근의 실패 양상을 우리는 세 가지로
관찰했다:

1. **정크 축적** — 실사용 8개월 된 호스티드 메모리 스토어(N=106)를 감사한 결과, 사용자에게
   durable한 가치가 있는 항목은 13개(12%)였다. 나머지 88%는 뉴스 조각, 프로브, 필러였다.
   저장은 공짜지만 회수 정밀도가 그 값을 치른다.
2. **시제 부재** — 유사도 검색은 사실의 유효 상태를 모른다. "지금 어디 사는가"류 질의에서
   낡은 사실이 최신 사실과 동등하게 랭크된다 (엔진의 stale-sibling 데모션이 이걸 보정하며,
   보정 임계값은 실측으로 캘리브레이션됨 — production embedding 기준 anchor→replacement
   유사도 0.73–0.85 대역).
3. **cold start** — 빈 스토어는 가치가 0이고, 사용자는 가치가 생기기 전에 이탈한다.

중심 주장(이 프로젝트의 정체성): **좋은 기억은 저장이 아니라 망각의 함수다.**
이는 인지과학의 오래된 결론과 정합한다 — Anderson & Schooler(1991)의 rational analysis는
인간 기억의 접근 확률이 환경 통계(사용 빈도·최근성)를 미러링함을 보였고, Ebbinghaus 이래
망각은 결함이 아니라 적응으로 재해석되어 왔다. 에이전트 메모리 문헌에서 이 관점은
아직 주변부다.

## 2. 관련 연구 지형 (2026-07 기준)

- **MemGPT/Letta** (Packer et al., 2023→): OS 페이징 은유의 계층 메모리. 관리 초점은
  컨텍스트 예산이지 기억의 질(정크·시제)이 아님.
- **Generative Agents** (Park et al., 2023): recency·importance·relevance 스코어링의 memory
  stream + reflection. 우리의 temporal rerank와 관찰 게이트의 개념적 선조. 단, 소셜 시뮬레이션
  맥락이며 provenance·supersession 없음.
- **Mem0 / Zep(Graphiti)** (2024–25 기술 보고서): 프로덕션 SaaS 메모리. Zep은 temporal KG로
  시제를 다루는 가장 가까운 이웃 — 차이: 서버측 평문 연산 전제, 그래프 구축 비용, 그리고
  둘 다 write-time 선택성(무엇을 아예 기억하지 않을 것인가)을 1급 문제로 다루지 않음.
- **HippoRAG** (2024): 해마 인덱싱 이론 기반 검색. 읽기 시점 개선 계열.
- **Reflexion** (Shinn et al., 2023): 에피소드 피드백의 언어적 축적 — 결과(outcome) 기억의 선조.
- **벤치마크**: LOCOMO(초장기 대화 회상), LongMemEval(2024–25, 상호작용 메모리의 5개 능력 축).
  공통 한계: 스토어가 벤치마크가 주입한 대화만으로 구성됨 — **오염된(정크 섞인) 스토어에서의
  회수**를 측정하는 벤치마크는 없다. 이것이 우리가 만들 수 있는 기여 지점.

우리 위치: 읽기 시점 개선(검색·그래프)이 아니라 **쓰기 시점 선택(관찰 게이트) + 사실 수명주기
(비파괴 supersession + 시간 인지 랭킹) + 프로세스 부산물 채굴(git)**의 결합. 부차 제약으로
로컬 퍼스트(프라이버시)가 아키텍처를 강제한다 — 제약이 아니라 실험 조건으로 취급한다.

## 3. 가설 (엔진이 이미 구현한 것의 반증 가능한 형태)

- **H1 (선택적 저장)**: 회수 정밀도는 read-time 랭킹보다 write-time 선택성에 더 민감하다.
  즉 정크율 p인 스토어의 precision@k 하락은 동일 랭커 개선으로 상쇄 불가능한 구간이 존재한다.
  예비 증거: 정크율 88% 실측 스토어의 체감 무가치("가치가 없는 것 같아" — 사용자 판정).
- **H2 (사실 수명주기)**: "현재 진실" 질의에서, 비파괴 supersession + stale-sibling 데모션은
  유사도-단독 검색 대비 정확도를 유의하게 올린다. 예비 증거: 엔진 테스트 스위트의 시나리오
  재현(테스트 9건) — 단, 합성 데이터. 실코퍼스 측정 필요.
- **H3 (프로세스 채굴)**: 결정형 기억은 자연 발생 프로세스 부산물(git 커밋)에서 룰 기반으로
  채굴 가능하며, 정밀도는 커밋 문화에 의존한다. 실측(선등록 시드 42, 샘플 20/리포):
  fastapi 60%, redis 70%, 추출률 1.4%/12.2%. 오탐 분류: 봇, 버전 화살표, 번역, 이유 없는
  rename — 각각 필터화됨 (45%/55%→60%/70% 개선 경로 기록).
- **H4 (스코프 격리)**: 다중 맥락 사용자(예: 두 회사 병행)에게 기억 격리는 검색 필터가 아니라
  1급 속성이어야 한다. 근거: 실사용 요구(N=1이지만 창업자 본인), 그리고 스코프 미지정 연결이
  회수 실패를 일으킨 실사고(2026-07-13, 스코프 라우트 부재로 신규 세션 회상 0).
- **H5 (로컬 제약 하의 품질)**: 온디바이스 추출·임베딩은 클라우드 대비 품질 격차 Δ가 존재하며,
  Δ는 태스크(결정 회상)에서 수용 가능 수준으로 좁힐 수 있다. 미측정 — E5가 다룬다.

## 4. 실험 프로토콜 (선등록 원칙: 기준 먼저, 결과 나중)

- **E1 — 오염 스토어 벤치마크 (신규 기여 후보)**: LongMemEval류 태스크에 통제된 정크
  주입률 p∈{0, 0.3, 0.6, 0.88}로 스토어를 오염시키고, (a) 게이트 있는 forget, (b) 게이트 끈
  forget, (c) 베이스라인(원문 RAG)의 precision@k·current-truth 정확도를 비교. H1의 직접 검정.
  산출물: "Dirty-Store Recall" 벤치마크 + 결과 노트.
- **E2 — LongMemEval 적합**: forget 어댑터를 작성해 공개 수치(Mem0, Zep 계열)와 나란히.
  목적은 SOTA 주장이 아니라 시제 축(temporal reasoning 항목)에서의 상대 강점 확인.
- **E3 — 망각 곡선 측정**: 도그푸드 스토어(현재 26+건, 성장 중)에서 기억의 나이 대비 회수
  유용성(세션이 실제로 인용했는가)을 종단 기록. temporal rerank의 감쇠가 Anderson-Schooler의
  환경 통계와 정합하는지 검정. 도구: 서버 로그에 recall-hit 계측 추가(로컬이므로 프라이버시
  문제 없음 — 본인 데이터).
- **E4 — 채굴 일반화**: 리포 20개(언어·커밋 문화 층화 표집)로 H3 정밀도 분포 추정,
  평가자 2인(본인+모델 채점)의 일치도 보고. 룰 대비 소형 로컬 LLM 추출기 비교.
- **E5 — 로컬 품질 격차**: deterministic-128 vs fastembed(bge-small) vs 클라우드 임베딩으로
  동일 질의셋 회수 품질 측정. vault 설계의 open crux #1을 실험으로 전환.
- **E6 — 파일 베이스라인**: 동일 사용 기간에서 forget vs 잘 관리된 CLAUDE.md의 회상 성능
  비교("이게 파일보다 나은 순간이 있었는가"의 정식화). 유일하게 이길 수 없는 조건(사용자가
  완벽한 사서일 때)을 명시하는 정직한 실험.

## 6. 이 어젠다의 실험 인프라 (이미 가동 중)

- 도그푸드 스토어: 본인 실사용 종단 데이터(launchd 상주, ~/.forget/), 선등록 판정 문화 확립
- 마이너 + 외부 코퍼스 파이프라인: blobless clone → 채굴 → 시드 고정 표본 채점 (E4 즉시 확장 가능)
- 엔진 자체: 게이트 on/off, rerank on/off가 전부 플래그/설정으로 절제 가능 — ablation-ready
- 미비: recall-hit 계측(E3 선행 요건), LongMemEval 어댑터(E2 선행 요건)
