# Recall v2 — 모델 진보에 배팅한 회상 설계

> 배팅 명제: 모델 인퍼런스는 계속 싸지고, 빨라지고, 좋아진다.
> 그렇다면 지능은 갈아끼우는 부품이고, 데이터만이 영속한다.
> (2026-08-03 정훈 발안. 이 문서가 이전의 "구조 레버" 초안을 대체한다.)

## 왜 뒤집었나

쓰기 시점 압축(추출·요약·색인)은 "읽기가 비싸다"에 대한 헤지다. 오늘의
게이트가 버린 정보는 내일의 더 좋은 모델이 영영 보지 못한다 — 압축은
미래 모델에 대한 역배팅이다. 반대로 읽기 시점 지능은 모델 곡선에
올라탄다: 모델이 좋아질 때마다, 재색인 없이, 저장된 모든 기억이 함께
좋아진다. 로컬 모델도 같은 곡선을 타므로 local-first 정체성과 충돌하지
않는다 — "완전 로컬인데 해마다 기억이 똑똑해지는 제품"이 이 배팅의 상품
형태다.

## 원칙

1. **데이터가 모델보다 오래 산다.** 진실의 원본은 원문 + 출처 + 시간이다.
   추출된 사실, 요약, 임베딩은 전부 *뷰*이며, 더 좋은 모델로 언제든
   재파생할 수 있어야 한다. 뷰 포맷이 데이터를 소유하게 두지 않는다.
2. **읽기는 2단 기어다.** 반사층(ms급, LLM 없음)은 대화의 리듬을 지키고,
   숙고층(LLM이 원문을 직접 읽음)은 품질을 끌어올린다. 모델이 싸질수록
   숙고층의 지분이 **재설계 없이** 늘어나도록 이음새를 미리 판다.
3. **지능층은 전부 일회용이다.** 게이트·캡슐·질의 계획·재랭크 — 어떤
   것도 상태를 소유하지 않고, 모델 교체로 통째 승급 가능해야 한다.

## 아키텍처

```
                    영속층 (배팅과 무관하게 생존)
        ┌──────────────────────────────────────────────┐
        │  에피소드: 원문, 무손실, 출처·시간·해시        │
        │  supersede 계보 (비파괴 정정 이력)             │
        └──────────────┬───────────────────────────────┘
                       │ 재파생 가능
        ┌──────────────┴───────────────────────────────┐
        │              지능층 (전부 뷰/캐시)             │
        │  사실 추출(게이트) · 요약(응고) · 임베딩 색인   │
        ├──────────────────────────────────────────────┤
        │  반사 회상: 다각(질의+엔티티+맥락) → RRF → MMR │  ← ms급
        │  숙고 회상: recall(query, budget) — LLM이      │  ← 모델 곡선에 탑승
        │            에피소드 원문을 직접 읽고 선별       │
        └──────────────────────────────────────────────┘
```

### 게이트의 재정의 — 문지기에서 편집자로

지금의 관찰 게이트는 "무엇을 기억할지"를 결정하며 탈락분을 버린다.
v2에서 게이트는 **무엇을 사실-뷰로 승격할지**만 결정한다. 원문은 항상
에피소드로 남는다(게이트 로그가 그 영수증). 따라서:

- `refine` (신설): 지정 범위의 에피소드에서 사실-뷰를 현재 모델로 재추출.
  모델이 좋아진 만큼 과거가 다시 읽힌다.
- 임베딩은 이미 캐시다 (`reembed` 존재). 청크 다중 벡터(장문)를 추가해
  512토큰 벽을 표현이 아니라 분할로 넘는다.

### 반사층 (지금 구현)

- **다각 검색, LLM 없이**: 원질의 + 엔티티 분해 + 최근 맥락어로 3~5각.
  스토어가 개인 규모라 다각의 비용이 사실상 0이다.
- **RRF 병합**: 각 질의의 순위만 사용 — 점수 눈금 문제 소멸.
- **MMR 선별**: "비슷한 기억 k개"가 아니라 "서로 다른 증거 k개".

### 숙고층 (이음새를 지금, 지분은 곡선을 따라)

- API: `recall(query, budget)` — budget이 기어를 고른다.
  budget=reflex(기본)는 위 반사층. budget=deliberate는 반사층의 후보 폭을
  넓게 가져와(예: 40) LLM이 원문 수준에서 읽고 고른다.
- 첫 소비자는 캡슐: "가장 유익한 과거 에피소드 1개"를 지목해 강조한다.
  (게이팅이 범용 메모리를 이긴다는 외부 검증: arXiv 2607.26611)
- 컨트롤러·리더 모델은 설정일 뿐이다. 로컬(Qwen급)로 시작해 모델 교체가
  곧 성능 릴리스가 되는 구조.

## 마이그레이션 (0.3.9 → 0.4.0)

| 단계 | 내용 | 측정 |
|---|---|---|
| M1 | 반사층: 다각+RRF+MMR | V1 held-out recall@k (오프라인, 무료) |
| M2 | 게이트 무손실화 + `refine` | 게이트 로그 → 에피소드 커버리지 100% |
| M3 | 장문 청크 다중 벡터 | 장문 프로브 적중률 |
| M4 | `recall(budget)` + 캡슐 최유익 에피소드 | 캡슐 채택률 (outcome flywheel) |
| M5 | 지속쓰기 웨지·dedupe 수정 동승 | 회귀 테스트 |

전 단계 공통: 레버 하나당 예측 선등록 → 오프라인 채점 (BENCH-LOOP 규율).
종합 검증은 CAPA식 자가 데모 — "forget 있음/없음의 첫 시도 성공률" —
그 숫자가 서면 밖에 말한다.

## 헤지

모델 진보가 정체하더라도 반사층이 제품을 온전히 지탱한다(현행과 동등
이상). 이 설계의 하방은 "지금과 같음"이고 상방은 "모델이 좋아질 때마다
공짜 성능"이다 — 비대칭이 배팅의 근거다.
