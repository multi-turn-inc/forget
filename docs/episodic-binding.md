# 일화 결합 (Episodic Binding) — 쓰기 경로 설계

2026-08-23. 밤샘 루프 9회차의 최종 진단에서 나온 설계다. 사양서는 신경과학이다.

## 문제 (실측)

조립 품질 평가셋(당일 확립 사실 8문항)에서 4/8. 추적 결과 병목은 조립도 임베딩도
아니라 **쓰기 경로**였다:

- `extract_facts`가 문단 → 문장 → 절로 원자화하면서 주제를 벗겨낸다.
- 실례: "캐시 배치 실측 완료 … 10턴 누적 A 3674 vs B 4601 토큰 = 20.1% 절감"이
  원장에는 `10턴 누적 A 3674 vs B 4601 토큰 = 20.1% 절감, 시간 5.0%.`로만 남았다.
  '캐시'도 '배치'도 'A/B가 무엇인지'도 없다.
- 최근 40건 표본 중 21건(52%)이 이런 맥락 없는 조각.
- 결과: 의역 질의("캐시 배치 실측 결과는?")가 어휘로도 의미로도 닿지 못하고,
  회상되더라도 읽는 쪽이 해독할 수 없다.
- 임베딩만 다국어로 바꿔도 효과 미미(정답 순위 270→245/291): 조각에 주제가
  없으면 어떤 임베딩도 살릴 수 없다.

## 원리 (인간 기억이 사양서다)

1. **결합(binding)** — 해마 부호화의 핵심은 사실을 맥락(무엇+어디+언제)과 한
   덩어리로 묶는 것이다. 사실이 단독으로 저장되는 일은 없다.
2. **요지+문면(fuzzy trace)** — 인간은 gist와 verbatim을 둘 다 저장하고, 인출은
   주로 gist를 단서로 verbatim에 닿는다.
3. **원자화 자체는 유지한다** — 중복 판정·supersede·기억 단위 피드백은 사실
   단위에서만 성립한다. 고칠 것은 쪼개는 행위가 아니라 **쪼개면서 끊는 결합**이다.

## 핵심 관찰: 일화는 이미 저장돼 있다

`add_memories`는 저장 전에 `create_event("ADD", payload, …)`로 **원문 전체를
이벤트로 보존한다.** 일화 저장소를 새로 만들 필요가 없다. 끊긴 것은 두 가지뿐:

- 사실 행 → 원본 이벤트로 가는 **링크**
- 사실 임베딩에 주제가 실리지 않는 **부호화**

## 설계

### 1. 앵커 유도 (쓰기 시점, 결정적·무LLM)

```
_episode_anchor(content) -> str | ""
```

- 원문(message content)의 **첫 문장**을 앵커로 쓴다. ≤100자 절단.
  (원장 문체 실측: 항목 대부분이 "주제 선언 (날짜, 맥락): 상세…" 구조라
  첫 문장이 곧 주제문이다.)
- 원문이 한 문장이면 앵커 없음 — 이미 자족적이다.
- LLM 요약을 쓰지 않는 이유: 쓰기 경로는 안전 최우선 지점이고(환각이 원장에
  들어가면 끝), 결정적 규칙이어야 게이트 로그·회계와 정합한다.

### 2. 저장 (스키마 변경 없음)

각 사실 행의 `metadata`에:

```json
"episode": {"event_id": "<ADD 이벤트 id>", "anchor": "<첫 문장>", "idx": 3, "n": 7}
```

- `event_id`: 원문 복원 경로 (`get_event`로 형제 사실·원문 전체 조회 가능).
- `idx/n`: 일화 내 위치 — "7조각 중 3번째"가 감사·재구성 단서가 된다.
- 첫 조각(주제문 자신)에는 anchor를 넣지 않는다 (자기 자신이 앵커).

### 3. 부호화 (임베딩에 결합을 싣는다)

```python
embed_input = f"{anchor} — {fact}" if anchor_applies(fact, anchor) else fact
embedding = embed_text(embed_input, project_id=project_id)
```

- `anchor_applies`: 앵커가 있고, 사실이 앵커의 머리 토큰을 이미 포함하지 않을 때만.
- **hash는 종전대로 bare fact로 계산** — 중복 판정 의미가 변하지 않는다.
- 표시 텍스트(`memory` 컬럼)도 bare fact 유지 — 원장 가독성·기존 소비자 불변.

### 4. 인출·조립 (읽는 쪽의 결합 복원)

- 어휘 경로: rule 점수 계산 시 `metadata.episode.anchor`도 매칭 대상에 포함.
- 조립기 렌더: 사실이 앵커 머리 토큰을 안 가지면 `"{anchor} — {fact}"`로 렌더
  (모델이 읽는 줄에만 적용, 저장본 불변).
- 선택: `expand_episode=true` 요청 시 event_id로 형제 조각을 묶어 원문 맥락 제공
  (v2 — 기본 꺼짐, 예산을 먹으므로).

### 5. 임베딩 모델 전환 (이차 레버, 같은 마이그레이션에 동승)

- `bge-small-en-v1.5`(영어 전용) → 다국어(`paraphrase-multilingual-MiniLM` 대역).
- 단독 효과는 미미함이 실측됐지만(245/291), 앵커와 결합하면 복리 기대.
- 설정 경로는 이미 있음(`effective_embedding_stack`) — 설정 변경 + 재임베딩.

### 6. 백필 마이그레이션 (게이트 필요 — 실DB 변경)

기존 7,292건: 각 기억의 ADD 이벤트를 역참조해 앵커를 유도하고 재임베딩.
- 로컬 fastembed라 비용은 분 단위.
- **실DB 쓰기이므로 실행은 게이트 뒤에서** — 백업 선행, 스크립트는 준비만.

## 사전 등록 판정 기준

같은 8문항 평가셋으로:

- 지지: 검색 단계 6/8 → **≥7/8**, 조립 후 4/8(예산채움 후 5/8) → **≥6/8**
- 후퇴 금지 가드: 문면 질의(예: "회상을 시스템 프롬프트 안에 두면" 0.91 1위)가
  1위를 유지해야 한다. 앵커는 더하기만 해야지 문면 매칭을 깎으면 실패.
- 부차 지표: 최근 40건 "단독 해독 가능" 비율 48% → 앵커 렌더 적용 시 ≥90%.

n=8이라 1문항 차이는 잡음이다 — 판정선(≥7/8, ≥6/8)은 2문항 개선을 요구하도록
잡았고, 같은 밤 승자의 저주에 데인 교훈을 반영한다.

## 결과 (2026-08-23 오후, 게이트 불요 4단계 구현 후)

구현: `episode_anchor`/`anchor_applies`(memory_engine) · `add_memories`의 metadata·부호화 ·
검색 앵커 어휘 가산(상한 0.12) · 조립 렌더 `_context_bind_anchor`. 테스트 8건 신규,
전체 632 통과.

**앵커 유도** — 실원장 ADD 원문 297건에 걸어 **98% 유도**, 길이 중위 24자. 규칙은
문체 실측으로 확정했다: 콜론 → 줄표 → 문장 끝, 단 **괄호 안 콜론은 경계가 아니다**
(`…쓰지 않는다 (정훈 지시: "…")`에서 첫 콜론을 잡으면 앵커가 문장 전체가 된다).
유도 실패 6건은 하나의 1인칭 서술문 — 주제 선언 구조가 아니므로 앵커 없음이 정답.

**A/B (`scripts/exp_episodic_binding.py`)** — 실원장 원문 30건을 임시 DB 두 개에
재생, 주제를 잃은 조각 164건에 앵커 주제어로 질의:

| 팔 | 조각 | top-10 적중 | 문면 1위 |
|---|---|---|---|
| 결합 on | 164 | **57.3%** | 99.4% |
| 결합 off | 164 | 11.0% | 100.0% |

차이 +46.3pp. **후퇴 금지 가드 통과** (문면 1위 −0.6pp = 164건 중 1건, 허용치 −1.0pp 내).

**이 숫자를 읽는 법 — 순환이다.** 질의를 앵커에서 기계적으로 유도했으므로 앵커를 실은
팔이 유리한 것은 설계상 당연하다. 확인된 것은 *배선이 작동한다*는 사실뿐이고, *설계가
옳다*는 독립 검증은 아니다. 43%는 결합 후에도 여전히 못 닿는다.

### 사전 등록 기준의 정정 (정직하게 기록)

위 §판정 기준의 n=8 평가셋은 **내가 쓴 문항**이어서 내가 만든 조립기를 심판할 자격이
없었다. 같은 날 원장을 뒤져 관측 라벨로 **평가셋 v1(133문항, 6층)**을 만들었고
(`scripts/build_eval_set.py`), 이후 판정의 정본은 이쪽이다.

기준을 사후에 갈아치우는 것은 사전 등록의 취지를 훼손하므로 두 가지를 병기한다:

- **독립 검증은 아직 불가하다.** v1의 기억은 전부 앵커 없는 구(舊) 항목이라, 백필
  (게이트 대기) 전에는 결합의 효과가 구조적으로 0으로 나온다. 즉 지금 v1을 돌려 나오는
  숫자는 결합의 성적이 아니다 — 그 사실을 모르고 "효과 없음"으로 읽으면 오독이다.
- **판정선은 백필 이후로 이월한다**: 백필 후 v1 `machine_resume` 층의 천장이 오르면
  지지, 문면 1위가 −1pp 이상 후퇴하면 반증.

### 부수적으로 드러난 것

- **`infer=False`는 원자화를 하지 않는다** — 원문이 한 덩어리로 남는다. 원장의 조각
  52%는 전부 `infer=True` 경로(훅·에이전트)산이다. 병의 소재가 좁혀졌다.
- **`anchor_applies`의 한 단어 함정** — 머리 토큰 하나만 겹쳐도 결합을 포기했다.
  "재현은 슬롯 캐시로 확인했다"가 우연히 '캐시'를 품었다는 이유로 주제를 못 받았다.
  둘 이상일 때만 자족으로 본다(테스트로 고정).
- **조립기에 건식 모드가 없었다** — `assemble_context`가 트레이스를 무조건 기록해서,
  평가 133회가 원장에 가짜 트레이스 133개를 남기고 그것이 다음 평가셋으로 재채굴됐다.
  `record_trace=False`를 추가했다(기본값 켜짐, 실사용 계측 불변).

## 하지 않는 것

- 원자화 중단 (중복·supersede·피드백의 전제)
- 쓰기 시점 LLM 재작성 (환각을 원장에 들일 수 없다)
- `memory` 컬럼 텍스트 변경 (기존 소비자·hash 의미 보존)
- 마이그레이션 무단 실행 (게이트 대기)
